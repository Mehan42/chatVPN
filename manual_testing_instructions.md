# Инструкция по ручному тестированию XVPN клиента

## Подготовка к тестированию

1. Убедитесь, что у вас установлен Go (версия 1.24 или выше)
2. Проверьте, что все зависимости обновлены:
   ```bash
   cd /home/uss/xvpn_client/xvpn-client-go
   go mod tidy
   ```

## Запуск клиента

1. Сборка клиента:
   ```bash
   go build -o xvpn-client ./cmd/xvpn-client
   ```

2. Запуск клиента:
   ```bash
   ./xvpn-client
   ```

## Что тестировать

1. **Запуск и инициализация**:
   - Клиент должен успешно запуститься
   - В логах должна появиться строка "✅ Обработчик проверки туннелирования интегрирован"
   - Машина состояний должна пройти через различные состояния

2. **Переходы между состояниями**:
   - Клиент должен пройти следующие состояния: initializing → config_fetching → config_validating → idle → starting → running
   - При переходе в состояние running, должен запуститься модуль проверки туннелирования

3. **Реакция на сигналы**:
   - Клиент должен корректно завершаться по сигналу (Ctrl+C)

4. **Интеграция с машиной состояний**:
   - При переходе в состояния stopping или idle, модуль проверки туннелирования должен останавливаться
   - При возврате в состояние running, модуль должен снова запускаться

## Тестирование в разных сценариях

1. **Нормальный сценарий**:
   - Запустите клиент
   - Дождитесь перехода в состояние running
   - Проверьте, что в логах нет ошибок
   - Завершите клиент (Ctrl+C)

2. **Сценарий с остановкой и запуском**:
   - Запустите клиент
   - Дождитесь состояния running
   - Имитируйте остановку VPN (через API или изменение конфигурации)
   - Проверьте, что модуль проверки туннелирования останавливается
   - Имитируйте повторный запуск
   - Проверьте, что модуль проверки туннелирования запускается снова

3. **Аварийный сценарий**:
   - Запустите клиент
   - Имитируйте сбой в работе VPN
   - Проверьте, что система корректно справляется с переходами между состояниями

## Ожидаемые результаты

1. Клиент успешно запускается и переходит через различные состояния
2. Модуль проверки туннелирования корректно интегрирован с машиной состояний
3. При переходе в состояние running, модуль проверки туннелирования запускается
4. При переходе в состояния stopping или idle, модуль проверки туннелирования останавливается
5. Клиент корректно реагирует на сигналы завершения

## Проверка логов

При тестировании обращайте внимание на следующие сообщения в логах:
- "✅ Обработчик проверки туннелирования интегрирован" - подтверждает успешную интеграцию
- "State transition: ... -> running" - момент запуска проверки туннелирования
- "State transition: running -> ..." - момент остановки проверки туннелирования

## Замечания

- В текущей реализации модуль проверки туннелирования запускает простые команды для демонстрации функциональности
- Реальные проверки туннелирования (проверка направления трафика, IP-утечки и т.д.) должны быть реализованы в будущем
- В тестовой среде могут возникать ошибки подключения к серверу API, это нормально для тестирования функциональности модуля
