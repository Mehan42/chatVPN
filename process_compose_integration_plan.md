# План интеграции Process Compose в XVPN клиент

## 1. Текущее состояние

XVPN клиент состоит из двух основных реализаций:
- Python GUI (chatvpn_gui.py) - прототип/альтернативная реализация
- Go клиент (xvpn-client-go) - основная, полнофункциональная версия с GUI на Fyne

Go клиент имеет следующую архитектуру:
- internal/state - машина состояний
- internal/geoip - маршрутизация трафика (РУ/неРУ)
- internal/transport - управление транспортами
- internal/config - система конфигурации
- internal/logging - система логирования
- internal/gui - графический интерфейс
- internal/api - клиентская библиотека XVPN API
- internal/health - система мониторинга здоровья
- internal/alerts - система алертов и уведомлений
- internal/updater - система обновлений
- internal/proxy - система прокси

## 2. Цель интеграции

Интегрировать Process Compose для управления процессами проверки туннелирования трафика неРУ сегмента, как описано в task_tunnel_verification.md.

## 3. Потенциальные изменения

### 3.1. Добавление Process Compose как зависимости

1. Добавить Process Compose в go.mod как зависимость:
   ```bash
   go get github.com/f1bonacc1/process-compose
   ```

2. Использовать внутренние пакеты Process Compose, при необходимости добавив replace директиву.

### 3.2. Модификация архитектуры

1. Создание нового модуля `internal/tunnelverifier` для проверки туннелирования трафика
2. Интеграция Process Compose для управления процессами проверки
3. Модификация машины состояний для управления процессами проверки
4. Интеграция с системой логирования

### 3.3. Конфигурационные изменения

1. Расширение конфигурации для поддержки Process Compose
2. Создание process-compose.yaml для определения процессов проверки туннелирования
