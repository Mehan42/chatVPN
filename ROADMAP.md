ChatVPN Roadmap (v0.2 → v0.3)
Этап 0 — Зафиксированная база (то, что уже есть)

Сервер Xray + Reality (Ubuntu 20.x, США) — есть

Telegram-бот (webhook), создание клиентов — есть

Клиент-GUI: статус IP, кнопка Вкл/Выкл, запрос конфига — есть

Локальные пути и договорённости по абсолютным путям — есть

Этап 1 — Включаем прямой канал конфигов (обязательно для тестов)

Цель: клиент стабильно получает client.json без Telegram.

 Сервер: подготовить HTTPS-раздачу конфигов и манифеста

Артефакты:

/opt/xvpn/data/clients/<UUID>/client.json (уже есть)

/opt/xvpn/data/transports/manifest.json (добавить, стартовая статичная версия)

Временный TLS (self-signed) только для тестов

Эндпоинты:

GET /clients/<UUID>.json

GET /transports/manifest.json

 Клиент: первичная логика загрузки:

Сначала тянуть client.json по HTTPS

Если нет — сообщить в GUI и предложить ручной вариант

Кэшировать манифест в ~/chatvpn/client/transports/manifest.json

Выходные критерии:

Кнопка «Запросить конфиг» в GUI получает файл напрямую

«Включить VPN» запускает Xray без ошибок

В логах фиксируется источник конфигурации (HTTPS)

Этап 2 — «Светофор» невидимости + базовые метрики

Цель: правдоподобная оценка маскировки (0–5) и прозрачные метрики.

 GUI: отрисовка индикатора (зел/жёлт/красн)

 Backend: сбор метрик

IP-утечка (внешний IP ≠ локальный)

Режим TLS/Reality (признаки валидности рукопожатия) — базовая эвристика

DNS: проверка DoH/DoQ vs. plain-DNS попыток

Паддинг/фрагментация (по профилю) — флаг от транспорта

 Логи: ~/chatvpn/client/logs/health.log

Выходные критерии:

Видим оценку 0–5, коррелирующую с выбранным транспортом

Поведение повторяемо на IPv4/IPv6

Этап 3 — Машина состояний и авто-переключение транспорта

Цель: автоматическое поддержание связи без «дёрганий».

 Реализовать состояния: DISCOVER → CONNECTING → ACTIVE → DEGRADED → FALLBACK → RECOVER

 Префлайт-тесты транспорта (v4/v6, TLS Hello, QUIC ping при need_udp)

 Гистерезис: min_hold_time, «окно деградации»

 Возвраты в приоритетные транспорты по расписанию

Выходные критерии:

При блоке/деградации T0 происходит плавный переход к T1/T2…

Возврат к T0 после стабилизации

Этап 4 — IPv6 и прокси-режимы

Цель: двусвязная живучесть и гибкость для приложений.

 Сервер: Xray слушает IPv6 ([::]), fw-правила актуальны

 Клиент: параллельный dial v4/v6, выбор по успеху/латентности

 Локальные прокси:

SOCKS5/HTTP на 127.0.0.1 (случайные порты)

Опция «только прокси» без TUN (корп. сети, captive-portal)

 GUI: переключатель режимов (TUN / Proxy / Auto)

Выходные критерии:

Тесты проходят при блоке UDP, при принудительном v6-трафике

Приложения могут указывать локальные прокси без TUN

Этап 5 — Доработки Telegram-бота (не блокирующие клиента)

Цель: админ-панель и масштабирование, без привязки клиента к webhook.

 Боту добавить REST-эндпоинты (только для админов)

 Команды для ротации ключей/реестра клиентов

 Лимиты на количество клиентов (по серверу/тарифам), квоты

Выходные критерии:

Админ-операции выполняются через бота/REST

Клиент не зависит от getUpdates вообще

Этап 6 — Безопасность и удобство

 Пиннинг публичного ключа HTTPS-раздачи

 Очистка/изоляция логов, минимизация PII

 Инсталляторы:

Клиент: .AppImage/.deb с меню-иконкой

Сервер: скрипт настройки HTTPS-раздачи (самоподписанный → продовый TLS позже)

Правила проекта

Простота > универсальность (каждый шаг — небольшой и проверяемый)

Все инструкции с абсолютными путями

GUI = один экран (статус, кнопка, светофор, минимум переключателей)

Бот ≠ жизненно важный для клиента (резерв/управление)

Никаких «магий» в обещаниях невидимости — только измеримые метрики

Чек-лист перед каждым релизом

Конфиги клиентов доступны на сервере

Прямой HTTPS-канал работает (ручная проверка curl)

Клиент поднимает T0, светофор ≥3

При искусственной блокировке T0 → переключение на T1/T2

Логи читаемы, пути совпадают, GUI не зависает

Процедуры (для удобства)

Проверить наличие конфига на сервере
!bash ls -la /opt/xvpn/data/clients/<UUID>/client.json !

Положить конфиг локально (временный тест)
!bash mkdir -p ~/chatvpn/client cp /путь/к/вашему/client.json ~/chatvpn/client/client.json !

Запустить мини-приложение клиента
!bash ~/chatvpn/client/dist/chatvpn_gui !

Ожидаемое поведение GUI

Кнопка «Включить VPN» поднимает Xray (~/chatvpn/client/xray -c ~/chatvpn/client/client.json)

Индикатор IP меняется на серверный

«Светофор» 0–5: зелёный при нормальной маскировке, жёлтый при компромиссах, красный при явных проблемах
