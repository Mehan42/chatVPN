# План миграции XVPN клиента с Python на Go

## Обзор

Данный документ описывает план миграции XVPN клиента с Python на Go для обеспечения мультиплатформенности. Go обеспечивает кроссплатформенную компиляцию, статическую типизацию и производительность, необходимые для расширения поддержки на MacOS, Windows, iOS и Android.

## Цели миграции

1. **Мультиплатформенность**: Возможность компиляции под разные операционные системы и архитектуры
2. **Производительность**: Более эффективное использование системных ресурсов
3. **Размер бинарного файла**: Меньший размер по сравнению с Python-приложением + интерпретатор
4. **Упрощение установки**: Одиночный бинарный файл без зависимости от интерпретатора
5. **Безопасность**: Снижение рисков, связанных с интерпретируемым кодом
6. **Разделение трафика**: Сортировка трафика на РУ и неРУ сегменты (РУ трафик через провайдера напрямую, неРУ через удаленный сервер)
7. **Мониторинг сервера**: Проверка работоспособности удаленного сервера с хаотичной частотой пинга

## Компоненты для миграции

### 0. Модуль маршрутизации трафика (geoip_router)

**Текущая функциональность из описания:**
- Сортировка трафика на РУ и неРУ сегменты
- РУ трафик направляется через провайдера напрямую
- неРУ трафик направляется через удалённый сервер с предварительной оберткой в протокол
- Использование LLM и базы данных на сервере для выбора протокола
- Балансировка, обработка и распределение трафика на сервере
- Проверка работоспособности сервера с хаотичной частотой пинга

**Go реализация:**
- Встроенный GeoIP модуль с базами внутри бинарника
- Алгоритмы определения принадлежности IP-адреса к РУ/неРУ регионам
- Механизмы разделения трафика на сегменты
- Модуль хаотичного пинга сервера для проверки доступности

### 1. Машина состояний (state_machine.py)

**Текущая функциональность:**
- Управление жизненным циклом VPN-соединения
- Состояния: INITIALIZING, IDLE, CONFIG_FETCHING, CONFIG_VALIDATING, STARTING, RUNNING, HEALTH_CHECKING, SWITCHING_TRANSPORT, STOPPING, ERROR, RECOVERING, UPDATING
- Обработка событий и переходов между состояниями
- Логирование переходов и состояний

**Go реализация:**
- Использование типов (enum) для состояний и событий
- Структура контекста для хранения состояния
- Функции для каждого состояния
- Система обработки событий через каналы

### 2. Система мониторинга здоровья (health.py)

**Текущая функциональность:**
- Проверка утечки IP (сравнение локального и внешнего IP)
- Анализ TLS-профиля и оценка безопасности
- Проверка соединения (DNS, TCP, HTTP)
- Расчет оценки маскировки (0-5)
- Поддержка IPv6

**Go реализация:**
- Использование стандартной библиотеки net для проверок
- HTTP клиент для проверки внешних IP-адресов
- TLS анализ через стандартную библиотеку crypto/tls
- Поддержка IPv6 через стандартные функции

### 3. Управление транспортами (transport_manager.py, discover.py)

**Текущая функциональность:**
- Обнаружение доступных транспортов
- Управление списком транспортов и приоритетами
- Поддержка различных протоколов (VLESS, VMess, Trojan, Shadowsocks, WireGuard)
- Поддержка IPv4/IPv6

**Go реализация:**
- Структуры данных для транспортов
- Алгоритмы обнаружения и выбора транспорта
- Поддержка всех протоколов через соответствующие библиотеки

### 4. GUI (chatvpn_gui.py)

**Текущая функциональность:**
- Основной интерфейс с индикаторами статуса
- Кнопки управления подключением
- Интеграция с системным трэем
- Визуализация оценки безопасности ("светофор")

**Go реализация:**
- Использование Fyne для кроссплатформенного GUI
- Интеграция с системным трэем через fyne
- Адаптивный интерфейс для разных платформ

### 5. Бэкенд (chatvpn_backend.py)

**Текущая функциональность:**
- Интеграция с VPN-движками (XRay и др.)
- Управление конфигурацией
- Запуск и остановка сервисов

**Go реализация:**
- Взаимодействие с VPN-движками через системные вызовы
- Управление конфигурацией через JSON

### 6. Мониторинг сервера (новый компонент на основе описания в файле "Выбор модуля для клиента.txt")

**Текущая функциональность из описания:**
- Проверка работоспособности удаленного сервера с хаотичной частотой пинга
- Следит за связью с удалённым сервером
- Проверка доступности сервера для обслуживания неРУ трафика

**Go реализация:**
- Модуль хаотичного пинга с изменяющимися интервалами (например, 30-300 секунд)
- Поддержка разных протоколов проверки (ICMP, HTTP health check)
- Механизмы переподключения при сбоях
- Система уведомлений о недоступности сервера

## Технические соображения

### Поддержка протоколов

Go имеет библиотеки для поддержки всех необходимых протоколов:
- VLESS, VMess, Trojan: github.com/xtls/xray-core (Go-версия)
- Shadowsocks: github.com/shadowsocks/go-shadowsocks2
- WireGuard: Использование системного WireGuard или golang.zx2c4.com/wireguard

### GUI фреймворк

Рассмотрены варианты:
- **Fyne**: Кроссплатформенный, хорошая поддержка, активное развитие
- **Wails**: Позволяет использовать веб-технологии для интерфейса
- **Gio**: Современный Go UI фреймворк
- **Gotk3**: Go биндинги для GTK

Рекомендуется использовать **Fyne** для лучшей кроссплатформенности и поддержки.

### Сборка под мобильные платформы

- **Android**: `gomobile` для сборки Android AAR или APK
- **iOS**: `gomobile` для сборки фреймворка для iOS

## Риски и митигация

### Риск: Сложность миграции сложной логики

**Митигация:** Постепенная миграция с сохранением тестов, обеспечивающих соответствие поведения

### Риск: Потеря функциональности

**Митигация:** Создание полной карты текущей функциональности с последующим пошаговым воссозданием в Go

### Риск: Производительность GUI

**Митигация:** Выбор подходящего фреймворка и оптимизация критических участков

## Критерии успеха

1. Go-версия обеспечивает ту же функциональность, что и Python-версия
2. Приложение компилируется под все целевые платформы
3. Производительность не хуже, чем у Python-версии
4. Размер бинарного файла приемлем
5. Успешные тесты на всех целевых платформах
6. Сохранение архитектурных принципов XVPN
