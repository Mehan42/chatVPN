
### **Архитектура: "Gateway"**

Мы создадим систему, состоящую из независимых, конфигурируемых "Шагов" (Steps), которые обрабатывают сетевые "События" (Events). Это ядро концепции Motia, адаптированное для сетевого уровня.

**Основные компоненты:**

1.  **Перехватчик Трафика (Traffic Interceptor):**
    *   **Задача:** Захватывать исходящие сетевые пакеты до того, как они покинут систему.
    *   **Реализация:** Использование `netfilter` через `libnetfilter_queue` в Linux. Это позволяет нам получить пакет в userspace, принять решение и либо изменить его, либо отправить дальше, либо отбросить. Модуль будет автоматически настраивать правила `iptables` для перенаправления трафика в свою очередь.

2.  **Движок Маршрутизации (Routing Engine):**
    *   **Задача:** Ядро системы, аналог `motia.ts`. Он получает "события" от перехватчика и последовательно пропускает их через зарегистрированные "Шаги".
    *   **Реализация:** Центральный диспетчер на Go, который использует каналы (channels) для передачи событий между шагами, обеспечивая асинхронную и неблокирующую обработку.

3.  **Шаги (Steps):**
    *   **Концепция:** Это модули, каждый из которых выполняет одну конкретную задачу. Они загружаются и конфигурируются динамически.
    *   **Типы шагов:**
        *   **`GeoIPStep`:** Определяет географическую принадлежность IP-адреса назначения. Использует локальную базу GeoLite2.
            *   **Вход:** Событие `NewConnection` с IP-адресом назначения.
            *   **Выход:** Генерирует событие `RouteDirectly` (для РФ) или `RouteViaTunnel` (для остального мира).
        *   **`PortCheckStep`:** Проверяет, соответствует ли трафик разрешенным портам (80/443). Хотя провайдер и так все блокирует, этот шаг может быть полезен для логики или будущих расширений.
        *   **`DirectRouteStep`:** Обрабатывает событие `RouteDirectly`. Его задача — "отпустить" пакет, отправив его в системный стек для обычной маршрутизации.
        *   **`TunnelRouteStep`:** Обрабатывает событие `RouteViaTunnel`. Его задача — инкапсулировать исходный пакет и передать его в `Менеджер Туннелей`.

4.  **Менеджер Туннелей (Tunnel Manager):**
    *   **Задача:** Управлять соединением с удаленным сервером (VPS), через который будет идти "не-РУ" трафик.
    *   **Реализация:** Так как открыты только 80/443 порты, туннель должен маскироваться под обычный HTTPS-трафик. Мы реализуем простой TLS-туннель (аналог `stunnel` или `xray` с протоколом `vless+tls`). Клиентская часть будет в нашем модуле, серверная — на VPS. Это обеспечивает неотслеживаемость провайдером, так как весь трафик будет выглядеть как зашифрованное HTTPS-соединение с каким-то сайтом.

5.  **Загрузчик Конфигурации (Config Loader):**
    *   **Задача:** Читать конфигурационный файл (например, YAML), который описывает, какие шаги включены, их параметры (путь к базе GeoIP, адрес туннельного сервера и т.д.) и правила фильтрации.

**Схема работы:**

```
[Браузер] -> [iptables] -> [Motia Gateway] -> [Решение]
                               |
                               v
                       [Traffic Interceptor]
                               |
                               v (событие NewConnection)
                       [Routing Engine]
                               |
                               v
                       [GeoIPStep]
                               |
          +--------------------+--------------------+
          |                                         |
(событие RouteDirectly)                  (событие RouteViaTunnel)
          |                                         |
          v                                         v
[DirectRouteStep]                        [TunnelRouteStep]
          |                                         |
          v (пакет в систему)                       v
   [Маршрут по умолчанию]                 [Tunnel Manager] -> [Интернет через VPS]
```

### **Стек Технологий**

*   **Язык:** **Go**. Идеально подходит для системного программирования, сетевых задач и создания высокопроизводительных, standalone-приложений.
*   **Перехват пакетов:** `github.com/florianl/go-nfqueue` — Go-обертка для `libnetfilter_queue`.
*   **GeoIP:** `oschwald/geoip2-golang` — стандартная библиотека для работы с базами MaxMind GeoLite2.
*   **Туннелирование:** Стандартная библиотека `crypto/tls` в Go. Мы создадим простой TLS-прокси, который будет выглядеть как обычное HTTPS-соединение.
*   **Конфигурация:** `gopkg.in/yaml.v3` для человекочитаемых YAML-файлов.
*   **Взаимодействие с ОС:** Пакеты `os/exec` и `os/signal` для управления `iptables` и graceful shutdown.

#### **1. Конфигурация (`config.yaml`)**

```yaml
# config.yaml
gateway:
  log_level: "info"

# Параметры для шагов
steps:
  geoip:
    enabled: true
    database_path: "/etc/motia-gateway/GeoLite2-Country.mmdb"
    # Список кодов стран для прямой маршрутизации
    direct_route_countries: ["RU"]

  tunnel:
    enabled: true
    remote_server: "your-vps.com:443" # Адрес вашего сервера
    # Для TLS можно добавить SNI для маскировки
    tls_sni: "cloudflare.com"

# Настройки перехватчика
interceptor:
  # Перенаправлять трафик только с этих портов
  redirect_ports: [80, 443]
  # Исключать локальные сети
  exclude_subnets: ["127.0.0.0/8", "192.168.0.0/16", "10.0.0.0/8"]
```

#### **2. Основные типы (аналог `types.ts` в Motia)**

`core/types.go`

```go
package core

import "net"

// Event - базовое событие в системе
type Event struct {
	Type string      // Тип события, например, "NewConnection"
	Data interface{} // Данные события, например, *PacketInfo
}

// PacketInfo - информация о перехваченном пакете
type PacketInfo {
	PacketID   uint32
	Payload    []byte
	DestIP     net.IP
	DestPort   int
	Protocol   string // "tcp", "udp"
}

// Step - интерфейс для всех шагов обработки
type Step interface {
	// Process обрабатывает событие и может вернуть новое событие
	Process(event Event, emit func(Event)) error
	// Name возвращает имя шага
	Name() string
}
```

#### **3. Шаг: GeoIPStep**

`steps/geoip_step.go`

```go
package steps

import (
	"errors"
	"fmt"
	"net"

	"github.com/oschwald/geoip2-golang"
	"motia-gateway/core"
)

type GeoIPStep struct {
	name     string
	db       *geoip2.Reader
	direct   map[string]bool
}

func NewGeoIPStep(dbPath string, directCountries []string) (*GeoIPStep, error) {
	db, err := geoip2.Open(dbPath)
	if err != nil {
		return nil, fmt.Errorf("failed to open geoip db: %w", err)
	}

	direct := make(map[string]bool)
	for _, c := range directCountries {
		direct[c] = true
	}

	return &GeoIPStep{
		name:   "GeoIPStep",
		db:     db,
		direct: direct,
	}, nil
}

func (s *GeoIPStep) Name() string { return s.name }

func (s *GeoIPStep) Process(event core.Event, emit func(core.Event)) error {
	if event.Type != "NewConnection" {
		return nil // Обрабатываем только новые соединения
	}

	info, ok := event.Data.(*core.PacketInfo)
	if !ok {
		return errors.New("invalid event data for GeoIPStep")
	}

	record, err := s.db.Country(info.DestIP)
	if err != nil {
		// Если не удалось определить, отправляем в туннель для безопасности
		emit(core.Event{Type: "RouteViaTunnel", Data: info})
		return nil
	}

	if s.direct[record.Country.IsoCode] {
		emit(core.Event{Type: "RouteDirectly", Data: info})
	} else {
		emit(core.Event{Type: "RouteViaTunnel", Data: info})
	}

	return nil
}
```

#### **4. Шаг: TunnelRouteStep**

`steps/tunnel_route_step.go`

```go
package steps

import (
	"fmt"
	"log"
	"motia-gateway/core"
	"motia-gateway/tunnel"
)

type TunnelRouteStep struct {
	name    string
	manager *tunnel.Manager
}

func NewTunnelRouteStep(remoteServer string) (*TunnelRouteStep, error) {
	manager, err := tunnel.NewManager(remoteServer)
	if err != nil {
		return nil, fmt.Errorf("failed to create tunnel manager: %w", err)
	}
	return &TunnelRouteStep{
		name:    "TunnelRouteStep",
		manager: manager,
	}, nil
}

func (s *TunnelRouteStep) Name() string { return s.name }

func (s *TunnelRouteStep) Process(event core.Event, emit func(core.Event)) error {
	if event.Type != "RouteViaTunnel" {
		return nil
	}

	info, ok := event.Data.(*core.PacketInfo)
	if !ok {
		return fmt.Errorf("invalid event data for TunnelRouteStep")
	}

	log.Printf("Routing packet to %s via tunnel", info.DestIP)
	// Отправляем данные в туннель. Менеджер сам разберется с инкапсуляцией.
	return s.manager.Send(info.Payload)
}
```

#### **5. Движок и Main (связующее звено)**

`main.go` (упрощенная версия)

```go
package main

import (
	// ... другие импорты
	"motia-gateway/core"
	"motia-gateway/steps"
	"motia-gateway/interceptor"
)

func main() {
	// 1. Загрузка конфигурации
	cfg, err := config.Load("config.yaml")
	if err != nil { /* ... */ }

	// 2. Настройка iptables (через interceptor.Setup())
	if err := interceptor.Setup(cfg.Interceptor); err != nil { /* ... */ }
	defer interceptor.Cleanup() // Гарантированная очистка при выходе

	// 3. Создание движка
	engine := core.NewEngine()

	// 4. Создание и регистрация Шагов
	geoStep, _ := steps.NewGeoIPStep(cfg.Steps.GeoIP.DatabasePath, cfg.Steps.GeoIP.DirectRouteCountries)
	engine.RegisterStep(geoStep)

	tunnelStep, _ := steps.NewTunnelRouteStep(cfg.Steps.Tunnel.RemoteServer)
	engine.RegisterStep(tunnelStep)

	// ... другие шаги ...

	// 5. Запуск перехватчика
	nfqInterceptor, err := interceptor.NewNFQueueInterceptor(engine.EventChannel)
	if err != nil { /* ... */ }
	go nfqInterceptor.Start() // Запускаем в отдельной горутине

	// 6. Запуск движка
	go engine.Start()

	// Ожидание сигнала для завершения (Ctrl+C)
	sigChan := make(chan os.Signal, 1)
	signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)
	<-sigChan
	log.Println("Shutting down...")
}
```

Этот подход позволяет легко добавлять новые "Шаги" (например, для блокировки рекламы, фильтрации по доменам, балансировки нагрузки между несколькими туннелями), не меняя ядро системы, что полностью соответствует философии Motia.
