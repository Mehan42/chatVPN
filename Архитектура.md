# Краткий обзор архитектуры (одно предложение)

Минимальный надёжный стек: **Linux + systemd** → **VPN (Xray/WG) как отдельный systemd-сервис** → **Control API (Flask, PEP 723 + uv) под systemd** → **MCP-шлюз** → **ИИ-агент (deterministic state machine + RAG + LLM aliases)** → **SQLite как единственная СУБД на диске** → **Telegram-бот для управления и on-demand отчётов**.

# Компоненты и роли (детально)

## 1) ОС и supervisor

* OS: минимальный Debian/Ubuntu (или аналог), только нужные пакеты.
* supervisor: **systemd** (не Docker).
  ! Здесь важная информация — systemd = основной способ обеспечить автозапуск и перезапуск.

**Примеры unit-файлов (пути абсолютные):**

* Flask API unit: `/etc/systemd/system/xvpn-api.service`
* VPN core unit: `/etc/systemd/system/xvpn-core.service`
* Agent unit: `/etc/systemd/system/xvpn-agent.service`

Пример (xvpn-api.service):

```ini
[Unit]
Description=XVPN Control API
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/xvpn/api
ExecStart=/usr/bin/uv run /opt/xvpn/api/app.py
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

## 2) VPN Core (data plane)

* Рекомендация: Xray с Reality/WS+TLS и WireGuard-over-TLS профилями.
* Unit-файл: `/etc/systemd/system/xvpn-core.service`
* Конфиги в `/etc/xvpn/` (например `/etc/xvpn/xray.json`), сертификаты в `/etc/xvpn/tls/`.

## 3) Control plane (MCP Gateway)

* Flask приложение (`/opt/xvpn/api/app.py`) — маленький REST/MCP шлюз.
* Запускается через `uv run` (PEP 723 в заголовке скрипта).
* Точки:

  * `/mcp/v1/vpn.fetch_manifest`
  * `/mcp/v1/vpn.fetch_client/<uuid>`
  * `/mcp/v1/vpn.health`
  * `/mcp/v1/agent.rotate/<uuid>`
  * `/mcp/v1/agent.report/<uuid>?since=...`
* Конфиги: `/opt/xvpn/api/config.yaml`
* SSL: TLS certs в `/etc/xvpn/tls/` (SNI/JA3 профили).

! Здесь важная информация — MCP используется как control plane, не как транспорт данных.

## 4) Agent — мозг (deterministic rules + RAG + model aliases)

* Расположение: `/opt/xvpn/agent/`
* Скрипт сервиса: `/opt/xvpn/agent/agent.py` (запускается systemd).
* Подкомпоненты:

  * **State Machine** (фиктурная логика, DISCOVER→CONNECT→ACTIVE→FALLBACK).
    Файл: `/opt/xvpn/agent/state_machine.py`
  * **Health checks** (локальные проверки, таймауты, минимальные баллы маскировки).
    Файл: `/opt/xvpn/agent/health.py`
  * **RAG / KB**: local files + optional small vector index (for quick retrieval).
    Папка: `/opt/xvpn/agent/knowledge/`
  * **Model aliases**: config mapping:
    `/opt/xvpn/agent/models.yaml`

    ```yaml
    aliases:
      local: "ollama://llama3-8b"    # example
      remote: "openrouter://gpt-4o"
    ```
  * **DB access**: `/opt/xvpn/agent/db.py` → SQLite файл `/opt/xvpn/agent/db/agent.db`
* Agent принимает решения в основном по правилам; LLM используется только на запрос аналитики/нештатных случаев.

## 5) DB — SQLite (рекомендация)

* Файл: `/opt/xvpn/agent/db/agent.db`
* DDL (пример):

* Путь бэкапа: `/opt/xvpn/agent/db/backups/agent.db.YYYYMMDD.bak`

## 6) RAG / Knowledge store

* Directory: `/opt/xvpn/agent/knowledge/`

  * `/opt/xvpn/agent/knowledge/protocols.md` — playbooks в markdown
  * `/opt/xvpn/agent/knowledge/fallback.json` — резервные ресурсы
  * `/opt/xvpn/agent/knowledge/case_studies/` — архивы прошлых инцидентов
* Retrieval: лёгкий BM25 / exact match; если нужно семантика — лёгкий local index (Pangolin/FAISS optional). Но базовый lookup обычно достаточен.

## 7) Logs, reports, rotation

* Client logs (user machine): `~/chatvpn/client/logs/`
* Agent logs: `/opt/xvpn/agent/logs/`
* Server aggregated logs: `/var/log/xvpn/`
* Rotation: daily cron job `/etc/cron.d/xvpn-logrotate` or use `logrotate` config:

  * keep 7 days, compress older, backup critical reports to `/opt/xvpn/agent/db/backups/`

## 8) Telegram bot & Admin

* Bot code: `/opt/xvpn/admin/tg_bot.py`
* Bot issues commands via MCP (secured with Bearer tokens).
* Example commands:

  * `/rotate <UUID>` — rotate client's credentials
  * `/report <UUID> [since]` — fetch report
  * `/status` — global health summary

# State-machine (поведение агента) — псевдокод

! Здесь важная информация — это ядро автоматической устойчивости.

```python
# state_machine.py (концепт)
state = "IDLE"
manifest = fetch_manifest()
while True:
    health = run_health_checks()
    if health.mask_score < MIN_MASK_THRESHOLD:
        log("MASK_FAIL", details=health)
        # try fallback transports
        next_t = select_next_transport(manifest, current_transport)
        if next_t:
            connect(next_t)
            wait(min_hold_time(next_t))
            continue
        else:
            # escalate
            run_playbook("no_transports")
    if transport_lost():
        log("TRANSPORT_LOST")
        fallback()
    sleep(poll_interval)
```

# Playbooks / инструкции агента (примеры)

Файлы: `/opt/xvpn/agent/knowledge/protocols.md`

Примеры (видно как записи в `protocols` таблице или MD):

* **T0 failed 3x**

  1. Switch to T1 (immediate).
  2. Log event.
  3. Push report to admin via TG.
  4. If T1 fails within 120s, apply `T2_priority++` and attempt T2.

* **API /manifest unreachable > 5min**

  1. Try fallback manifest URLs from `fallback.json`.
  2. If none reachable, switch to proxy-only mode (local SOCKS) and notify admin.

* **All transports down**

  1. Start local debug collection: gather `/var/log/xvpn/*`, `journalctl -u xvpn-core -n 1000`, package into `/opt/xvpn/agent/logs/case_<ts>.tar.gz`.
  2. Attempt DNS and DoH tests.
  3. If unsuccessful, send minimal report to admin and set status `MANUAL_INTERVENTION_REQUIRED`.

# MCP — список методов (пример)

* `vpn.fetch_manifest() -> manifest.json`
* `vpn.fetch_client(uuid) -> client.json`
* `vpn.health() -> {mask_score, transports_status}`
* `agent.analyze_logs(since, tail) -> analysis_text` (calls LLM alias if needed)
* `agent.rotate(uuid) -> status`
* `agent.report(uuid, since) -> tar.gz` (on-demand)
* `admin.exec(cmd, args) -> result` (restricted)

# Почему SQLite + lightweight RAG (файловая KB) — правильный выбор

* Минимальный стек → **один файл DB**, легко бэкапить/реплицировать.
* Нет лишних демонов (как у Redis или Qdrant).
* Небольшие тексты и playbooks не требуют векторного поиска; retrieval по ключевым словам / BM25 хватает.
* Если потом потребуется семантика — можно добавить локальный вектор индекс (опционально) без ломки архитектуры.

# Безопасность и приватность (обязательные пункты)

* TLS: certs в `/etc/xvpn/tls/`, автоматическое обновление/замена; pinning на клиента для manifest.json.
* Логи: не сохранять PII (user payload), хранить только метрики и события.
* Аутентификация MCP: Bearer tokens, ротация ключей каждые N дней.
* Доступ к DB и knowledge folder: права `root:root` 600/700.
* Резервные manifest’ы в публичных CDN: хранить только минимальные статические копии, подписанные ключом.

# /// script

# requires-python = ">=3.10"

# dependencies = \["python-telegram-bot==13.15"]

# ///

import os, logging
from telegram.ext import Updater, CommandHandler

BOT\_TOKEN = os.environ.get("BOT\_TOKEN")
CHAT\_ID = os.environ.get("CHAT\_ID")

logging.basicConfig(level=logging.INFO)

def start(update, context):
if str(update.effective\_chat.id) != CHAT\_ID:
return
update.message.reply\_text("XVPN bot ready.")

def report(update, context):
if str(update.effective\_chat.id) != CHAT\_ID:
return
update.message.reply\_document(open("/opt/xvpn/agent/logs/agent.log"))

updater = Updater(BOT\_TOKEN, use\_context=True)
dp = updater.dispatcher
dp.add\_handler(CommandHandler("start", start))
dp.add\_handler(CommandHandler("report", report))

updater.start\_polling()
updater.idle()

# 2. Скрипт установки клиента

\#!/bin/bash
set -e

# Базовые пакеты

sudo apt update
sudo apt install -y python3 curl jq uv

# Директории

mkdir -p \~/chatvpn/client/{clients,transports,logs}

# Примеры файлов-заглушки

cat > \~/chatvpn/client/health.py <<'EOF'

# /// script

# requires-python = ">=3.10"

# dependencies = \[]

# ///

import time, random

LOG\_FILE = "/home/\$USER/chatvpn/client/logs/health.log"

def check\_ip\_leak():
return random.choice(\[True, True, False])

def check\_tls\_profile():
return random.randint(1, 5)

def get\_mask\_score():
score = 0
if check\_ip\_leak():
score += 2
score += check\_tls\_profile()
return min(score, 5)

def log\_health():
with open(LOG\_FILE.replace("\$USER", **import**("getpass").getuser()), "a") as f:
f.write(f"{time.time()} score={get\_mask\_score()}\n")

if **name** == "**main**":
log\_health()
print("Health logged:", get\_mask\_score())
EOF

cat > \~/chatvpn/client/state\_machine.py <<'EOF'

# /// script

# requires-python = ">=3.10"

# dependencies = \[]

# ///

import time, os, json

STATE\_LOG = f"/home/{os.getlogin()}/chatvpn/client/logs/state.log"
MANIFEST = f"/home/{os.getlogin()}/chatvpn/client/transports/manifest.json"

class StateMachine:
def **init**(self, manifest):
self.manifest = manifest\["transports"]
self.active = None

```
def discover(self):
    for t in self.manifest:
        self.log_state(f"DISCOVER {t['id']}")
        time.sleep(1)
        if t["id"] == "T0":
            return t
    return None

def connect(self, transport):
    self.active = transport
    self.log_state(f"CONNECTING {transport['id']}")
    time.sleep(1)
    self.log_state(f"ACTIVE {transport['id']}")

def fallback(self):
    idx = self.manifest.index(self.active)
    if idx + 1 < len(self.manifest):
        nxt = self.manifest[idx + 1]
        self.connect(nxt)
    else:
        self.log_state("NO_TRANSPORTS_LEFT")

def log_state(self, msg):
    with open(STATE_LOG, "a") as f:
        f.write(f"{time.time()} {msg}\n")
    print(msg)
```

if **name** == "**main**":
if not os.path.exists(MANIFEST):
raise SystemExit("manifest.json not found")

```
manifest = json.load(open(MANIFEST))
sm = StateMachine(manifest)
t = sm.discover()
if t:
    sm.connect(t)
else:
    sm.log_state("DISCOVER_FAILED")

# эмуляция отказа
time.sleep(3)
sm.log_state("SIMULATED_FAIL")
sm.fallback()
```

EOF

echo "Client installed. Put client.json into \~/chatvpn/client/clients/"

# 3. Поток работы клиента

1. TG-бот шлёт файл `client.json` с UUID.
   Вы сохраняете его в:
   `~/chatvpn/client/clients/<UUID>.json`

2. Манифест (`manifest.json`) автоматически тянется с сервера:

   ```bash
   curl -sk https://<SERVER_IP>:8443/transports/manifest.json \
     -o ~/chatvpn/client/transports/manifest.json
   ```

3. Проверка здоровья:

   ```bash
   uv run ~/chatvpn/client/health.py
   cat ~/chatvpn/client/logs/health.log
   ```

4. Запуск state machine:

   ```bash
   uv run ~/chatvpn/client/state_machine.py
   cat ~/chatvpn/client/logs/state.log
   ```

# ! Здесь важная информация
Добавляем **systemd unit** для клиента, чтобы при старте ПК автоматически запускался `state_machine.py` и вёл логи в `~/chatvpn/client/logs/state.log`.

# 1. Unit-файл для клиента

Файл: `~/.config/systemd/user/xvpn-client.service`
!\`\`\`ini
\[Unit]
Description=XVPN Client State Machine
After=network-online.target
Wants=network-online.target

\[Service]
Type=simple
ExecStart=/usr/bin/uv run /home/%u/chatvpn/client/state\_machine.py
Restart=always
RestartSec=10
WorkingDirectory=/home/%u/chatvpn/client
StandardOutput=append:/home/%u/chatvpn/client/logs/client\_stdout.log
StandardError=append:/home/%u/chatvpn/client/logs/client\_stderr.log

\[Install]
WantedBy=default.target
!\`\`\`

# 3. Логика работы

* При загрузке ОС запускается `xvpn-client.service`.
* Он вызывает `uv run ~/chatvpn/client/state_machine.py`.
* Все stdout/stderr пишутся в:

  * `~/chatvpn/client/logs/client_stdout.log`
  * `~/chatvpn/client/logs/client_stderr.log`
* Внутренние переходы state machine пишутся в `~/chatvpn/client/logs/state.log`.
